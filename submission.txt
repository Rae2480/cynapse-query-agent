CYNAPSE: NATURAL-LANGUAGE CCTV METADATA QUERY AGENT

Run
Python 3.11+. Create/activate a virtual environment and install:
  pip install -e '.[dev,openai]'
Export OPENAI_API_KEY and CYNAPSE_MODEL=openai:gpt-5-mini in your terminal.
.env files are not loaded automatically. Never submit your real API key or .env.
  cynapse seed
  cynapse chat --ai
Use --nonai for the deterministic version. Commands: next, previous, reset, exit.

Design and choices
app.py selects the version; orchestration.py wires individual functions in agents/.
OpenAI gpt-5-mini interprets intent and explicit filter changes into a strict
Pydantic schema. It does not generate SQL. Python resolves camera names, calendar
windows, daily times and weekdays, then validates a query plan. SQLite uses fixed,
parameterized SELECT statements through a read-only connection. This separates
flexible interpretation from reproducible date and database behavior. LangGraph
provides explicit routing and isolated conversation state. The nonai version
shares the resolution, validation and query stages.

Dataset and behavior
Simulation creates one frame every five minutes for all ten specified cameras
from January 1, 2026 through the current time. Records contain integer frame_id,
ISO datetime and canonical enum camera_name. Seeding is repeatable. Calendar
reasoning uses Singapore time, Monday-start weeks, inclusive start/exclusive end
and 2026 when the year is omitted. Results have exact totals and 20-record pages.

Context and guardrails
Only the current request, accepted filters and one pending clarification reach
the model; transcripts and returned frames are never sent. Context expires after
30 idle minutes and explicit reset clears it immediately. Requests are capped at
1,000 characters, filter expressions at 160 and clarification questions at 240.
Follow-ups preserve omitted filters; explicit changes replace them and clear
removes restrictions. Rejections and failures preserve valid context. Independent
requests do not merge unfinished filters. The model rejects unrelated, sensitive,
image-content, injection and database-write requests. Schema/date/name validation
precedes SQL. Model timeouts and malformed output produce safe errors, not queries.
The application handles explicit provider refusals separately. Seeding is the
only write path; natural-language requests cannot run arbitrary database commands.

Verification (2026-10-20)
301 local tests passed. Paid tests skip unless CYNAPSE_LIVE_TESTS=1.
Live gpt-5-mini: all 46 full-agent cases and 18 extraction cases passed after an
initial full run, fixes and targeted reruns. Cases cover all assignment examples,
all ten cameras, typos, aliases, boundaries, invalid/future dates, recurring and
combined filters, guardrails, clarification answers, resets and rejected turns.
Separate tests verify bounded 25-turn payloads, idle expiry, timeout/malformed
output handling, thread isolation and complete pagination without duplicate IDs.

  pytest -q
  CYNAPSE_LIVE_TESTS=1 pytest -q tests/test_assignment_inputs.py -k openai

Limits
Multiple cameras, overnight daily windows, multiple weekdays, exclusions and
ambiguous numeric dates require clarification. State is process-local; there is
no image analysis, persistent chat history or production deployment. Live results
are one evaluation pass with targeted reruns, not a statistical accuracy estimate.
API cost reporting is intentionally omitted in this minimal build.

Code walkthrough

Application
  src/cynapse/__init__.py: Marks the application as a Python package.
  src/cynapse/app.py: Reads terminal commands, selects AI/nonai mode and starts chat or seeding.
  src/cynapse/orchestration.py: Connects agents with LangGraph and keeps each conversation separate.
  src/cynapse/state.py: Defines the state fields shared by the agents.
  src/cynapse/data_models.py: Defines supported cameras and validates extraction updates and query plans.
  src/cynapse/settings.py: Stores the timezone, timeout, context expiry and input-size limits.
  src/cynapse/prompt.py: Tells the model how to interpret requests and reject unsupported ones.
  src/cynapse/openai_client.py: Calls OpenAI for structured extraction and handles failures and refusals.
  src/cynapse/nonai_extractor.py: Interprets supported requests with Python rules, without API calls.
  src/cynapse/context_manager.py: Merges follow-ups, saves unfinished queries and clears search context.
  src/cynapse/camera_resolver.py: Matches camera acronyms, full names, aliases and small typos.
  src/cynapse/time_resolver.py: Converts date, time and weekday expressions into precise boundaries.
  src/cynapse/query_planner.py: Combines extracted changes and inherited filters into a query plan.
  src/cynapse/database_manager.py: Generates frame records and runs parameterized, read-only queries.
  src/cynapse/agents/__init__.py: Marks the agents folder as a Python package.
  src/cynapse/agents/context_guard.py: Expires idle context and blocks oversized requests before interpretation.
  src/cynapse/agents/context_resetter.py: Clears filters, pending questions and pagination for a new search.
  src/cynapse/agents/intent_extractor.py: Runs the selected extractor and prepares this turn for resolution.
  src/cynapse/agents/filter_resolver.py: Builds a candidate plan or preserves unresolved filters for clarification.
  src/cynapse/agents/query_validator.py: Clips the candidate to available dates and prevents invalid queries.
  src/cynapse/agents/database_reader.py: Fetches a result page and formats records, filters and page information.
  src/cynapse/agents/page_navigator.py: Handles next/previous commands using the accepted filters.
  src/cynapse/agents/answerer.py: Returns clarification, rejection and error messages.
  src/cynapse/agents/nonai_interpreter.py: Adapts an optional custom callable that produces query plans directly.

Evaluation tools
  evaluations/__init__.py: Marks the evaluation tools as a Python package.
  evaluations/evaluate_local.py: Measures deterministic resolution and SQLite performance without OpenAI.
  evaluations/evaluate_agent.py: Runs full conversations and checks returned filters, records and guardrails.
  evaluations/evaluate_extraction.py: Checks selected fields in model output without running database queries.

Tests
  tests/test_agent.py: Checks basic queries, context, result limits and unsupported requests.
  tests/test_agent_evaluation.py: Checks evaluation grading and stopping on authentication failures.
  tests/test_assignment_inputs.py: Runs assignment examples without AI and all opt-in live AI cases.
  tests/test_camera_resolver.py: Checks camera matching, aliases, typos and ambiguity.
  tests/test_chat_regressions.py: Checks CLI mode selection, database refresh and checkpoint restoration.
  tests/test_conversation.py: Checks follow-ups, clarification, resets, isolation and bounded context.
  tests/test_evaluation.py: Runs the shared acceptance cases against the nonai version.
  tests/test_openai_client.py: Checks model configuration, structured output, timeouts and safe failures.
  tests/test_pagination.py: Checks page navigation, boundaries and complete retrieval without duplicates.
  tests/test_time_resolver.py: Checks dates, times, weekdays, invalid inputs and availability clipping.

Supporting files
  tests/evaluation_cases.json: Requests and expected results for acceptance tests.
  tests/extraction_cases.json: Requests and expected fields for model-only checks.
  pyproject.toml: Package dependencies, installation and the cynapse command.
  .gitignore: Keeps credentials, environments and generated files out of Git.
  README.md: Quick setup and commands.
  submission.txt: Design explanation, verification results and this walkthrough.
